Overview

Delulu Social — integration layer consolidation spec

Problem

Platform integration logic is split across six or more locations. There is no single registry and no shared interface. Adding one network requires touching a dozen files, and the same facts (OAuth scopes, character limits, default settings) are duplicated in multiple packages.

LocationWhat it does today
packages/worker/providers/index.ts providerRegistry — publish() only, 10 providers (~4,850 LOC)
packages/worker/providers/types.ts Minimal SocialProvider interface; returns neverthrow Result
packages/api/services/connect-url.service.ts connectUrlRegistry — OAuth URLs only; scopes duplicated vs callbacks
apps/app/app/api/callback/{platform}/route.ts 9 hand-rolled Next.js OAuth callback routes
apps/app/lib/platform-rules.ts ~1,070 LOC — media rules, character limits, video validation
packages/validators/constants/settings.ts Per-platform Zod defaults (PLATFORM_DEFAULT_SETTINGS)
packages/api/router/social-provider.ts Platform-specific queries (TikTok creator info, Instagram posts/stories, Facebook pages); inline TikTok token refresh

Cost today: adding one platform means new files in worker, API connect registry, callback route, platform-rules, validators, optional UI components, and env vars — with no compile-time guarantee they stay in sync.

Goal

Introduce packages/integrations as the single source of truth for all 10 publishable networks. Each platform is one folder exporting a PlatformIntegration object (meta, auth, rules, settings, publish). All consumers import from one registry.

  • Remove neverthrow from the integration layer — plain async + IntegrationError
  • Delete packages/worker/providers/ after full migration
  • Delete connect-url.service.ts after full migration
  • Replace 9 callback routes with one dynamic route

Success criteria

  • A developer can implement Phase 1 from this spec without prior codebase knowledge.
  • PlatformIntegration is complete enough to type-check (04 Types).
  • Instagram is traced end-to-end: OAuth → webhook subscribe → publish → DM automation link.
  • Adding a platform post-migration is ≤5 steps (06 Checklist).
  • Lambda+SQS publish path is unchanged; Convex remains data/scheduling/approvals source of truth.

Non-goals (v1)

  • New platform additions (e.g. Reddit)
  • Migration away from Lambda+SQS or Convex
  • Job pipeline hardening (DLQ, idempotency envelope) — see 07 Out of scope
  • Call Me Later → Convex scheduler replacement
  • Analytics unification across platforms
