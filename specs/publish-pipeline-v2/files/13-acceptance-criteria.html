Acceptance Criteria

Testable conditions for ship readiness.

AC-1: Failed publish never corrupts post state

TestExpected
Publish to IG + Twitter; IG succeeds, Twitter permanent fail publishStatus: PARTIAL; lifecycleStatus unchanged; IG job PUBLISHED, Twitter job FAILED
Transient failure on single provider Post content, schedule, reviewStatus unchanged; only job status updates
Org post not approved createPublishRun rejects; no jobs created

AC-2: Automatic retries with max attempts + dead letter

TestExpected
Simulate RATE_LIMIT_EXCEEDED Job requeued; attemptCount increments; backoff applied
5 transient failures Job → DEAD_LETTER; message in SQS DLQ
INVALID_ACCESS_TOKEN Job → FAILED immediately; no requeue; SQS message deleted

AC-3: Publish audit log per attempt

TestExpected
Single publish with 2 retries then success 3 publish_attempts rows: FAILED, FAILED, SUCCEEDED
GET /v1/posts/:id/publish-jobs Returns jobs with nested attempts, error codes, durationMs

AC-4: Zero-downtime migration

TestExpected
Deploy Phase 1–3 during business hours Existing scheduled posts still fire; no failed publishes attributable to deploy
Rollback flag PUBLISH_PIPELINE_V2=false Old path works within 5 minutes

AC-5: Manual retry

TestExpected
Dashboard retry on FAILED post New runId; jobs for failed providers only; UI shows IN_PROGRESS
post-card retry Same as above via tRPC/API

AC-6: Moats preserved

TestExpected
IG comment → DM automation Still works; linkPublishedPost fires from job completion
Org member submits post for review Approval flow unchanged; publish blocked until APPROVED

AC-7: Idempotency

TestExpected
Duplicate SQS delivery same publishJobId At most one platform post created; second completion no-op or updates same attempt

Verification checklist (pre-merge Phase 3)

  • Unit tests: derivePostPublishStatus all combinations
  • Unit tests: isRetryableError classification
  • Integration: publish to test IG sandbox account
  • Integration: multi-provider PARTIAL scenario (mock one provider fail)
  • Load: 10 concurrent publishes — no status corruption
  • Convex subscription: dashboard updates within 2s of job completion
