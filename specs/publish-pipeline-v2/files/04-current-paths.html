04 — Current Paths

Concrete code paths, file touchpoints, and coupling in today's publish system.

Path A — Publish now (REST API)

apps/app (use-post-actions.ts)
  → packages/api router (post mutation)
    → post.service.ts :: createPostInQueue(post)
      → for each socialProvider:
          → fetch(LAMBDA_URL, { socialType, socialPublishInput })
            → packages/infrastructure/src/trigger-sqs.ts
              → SQS SendMessage
                → packages/infrastructure/src/social-post-worker.ts
                  → packages/worker/client.ts :: processMessage()
                    → providerRegistry[socialType].publish()
                    → convex.mutation(api.posts.updatePostPublishStatus)

Coupling notes

  • createPostInQueue hardcodes Lambda URL (not SST Resource)
  • No post status transition to PROCESSING before queueing
  • Loop is sequential HTTP — slow for many providers
  • Throws on first queue failure; remaining providers never enqueued

Path B — Scheduled publish (Convex)

CallMeLater webhook
  → convex/http.ts
    → internal.posts.publishScheduledPost
      → for each socialProvider:
          → fetch(POSTING_LAMBDA_URL, { socialType, socialPublishInput })
            → (same SQS → Worker → Convex path as Path A)
      → on catch: internal.posts.updatePostStatus(FAILED)

Coupling notes

  • Duplicate queueing logic between post.service.ts and publishScheduledPost
  • Approval check (reviewStatus === "APPROVED") only in scheduled path
  • Queue failure marks entire post FAILED even if zero providers attempted

Path C — Worker completion

packages/worker/client.ts :: processMessage(messageBody)
  1. JSON.parse → { socialPublishInput, socialType }
  2. resolveMediaUrls(socialPublishInput)
  3. providerRegistry[socialType].publish({ content, socialProviderId })
  4. if Err → updatePostPublishStatus(FAILED, { failureReason })
     if Ok  → updatePostPublishStatus(PUBLISHED, { platformPostId, platformPostUrl })

Side effects in updatePostPublishStatus

File: packages/database/convex/posts.ts (line ~790)

  1. Patch posts.status to PUBLISHED or FAILED
  2. Upsert entry in platformPosts[]
  3. replacePostAggregate for dashboard stats
  4. If PUBLISHED: stats.addPublishDateInternal (streak)
  5. If PUBLISHED + platformPostId: automations.linkPublishedPost
  6. If PUBLISHED: schedule video cleanup via callmelater.scheduleVideoCleanupAction
Race condition

Steps 1–6 run per worker invocation with no locking. Two workers finishing concurrently can interleave patches — last write to posts.status wins regardless of per-platform outcomes.

No publishJobId, no attemptNumber, no idempotencyKey.
