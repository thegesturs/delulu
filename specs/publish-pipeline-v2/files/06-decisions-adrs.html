06 — Decisions & ADRs

Architecture decision records for Publish Pipeline v2.

ADR-001

Convex remains system of record

Accepted
Context

Publishing fragility stems from missing orchestration, not from Convex itself. A PlanetScale migration would take ~2–3 months and block all feature work.

Decision

Keep Convex as the primary database. Add publish_jobs and publish_attempts tables within Convex. Defer any SQL migration.

Consequences

Fast path to reliability (~3–4 weeks). Convex query/subscription model preserved. Must design indexes carefully for job sweeper queries.

ADR-002

One publish_job per post × social provider per run

Accepted
Context

Multi-platform posts need independent retry, status, and observability per target. A single job for all platforms cannot express partial success.

Decision

createPublishRun creates N jobs for N providers. Each job has its own SQS message, state machine, and attempt log. Jobs share a runId for grouping.

Consequences

Enables per-platform status chips and selective retry. Slightly more SQS messages (already one per provider today).

ADR-003

Post publishStatus derived from jobs; never set by worker alone

Accepted
Context

Workers racing to set posts.status cause partial-failure corruption. Post-level status must be a pure function of child job states.

Decision

Introduce posts.publishStatus (QUEUED, PROCESSING, PARTIAL, PUBLISHED, FAILED). Updated only by derivePostPublishStatus() after any job transition. Workers cannot write post fields directly.

Consequences

Eliminates race conditions. Dashboard must read publishStatus for publish state and status for lifecycle. Migration requires UI updates.

ADR-004

Worker writes via apps/api /internal/publish/* (HMAC auth)

Accepted
Context

Workers currently call public Convex mutations with admin credentials. No request validation, idempotency enforcement, or audit trail at the boundary.

Decision

Workers POST to apps/api internal routes authenticated with HMAC-SHA256 (WORKER_HMAC_SECRET). API calls Convex mutations internally. Remove direct convex.mutation(api.posts.updatePostPublishStatus) from worker.

Consequences

Single gateway for worker writes. Enables structured logging, rate limiting, and future auth rotation. Adds one network hop (Lambda → API → Convex).

ADR-005

Webhooks move to CF Workers in Phase 4; Instagram stays on AWS Lambda

Accepted
Context

Inbound webhooks are scattered across Lambda handlers and Convex HTTP endpoints. Instagram DM automations have complex session state requiring the existing Lambda path.

Decision

Phase 4 routes generic platform webhooks through apps/api/webhooks/*. Instagram DM webhooks remain on the existing AWS Lambda handler. Dual endpoints during cutover window.

Consequences

Documented now, implemented after pipeline cutover. Instagram path unchanged — zero risk to automations.

ADR-006

Keep Convex subscriptions for real-time dashboard

Accepted
Context

The dashboard relies on Convex reactive queries for live post status updates. Polling or SSE would degrade UX.

Decision

No change to subscription model. publish_jobs can optionally be subscribed to for per-platform chips, but primary UI reads derived posts.publishStatus and platformPosts.

Consequences

Zero frontend infrastructure change for real-time. Job table subscriptions available for advanced UI later.

ADR-007

Partial publish shows PARTIAL + per-platform status chips

Accepted
Context

Users publishing to multiple platforms need to see which succeeded and which failed, with retry affordance per failed platform.

Decision

When jobs are mixed PUBLISHED + FAILED, post publishStatus = PARTIAL. Dashboard renders per-platform chips from publish_jobs or platformPosts. Retry button re-runs only failed jobs.

Consequences

Requires UI work in Phase 3. Significantly improves multi-platform UX.

ADR-008

Grandfather FREE users; block new FREE signups

Accepted
Context

FREE tier is being deprecated. Existing users should not be disrupted. New specs should not reference FREE as an available plan.

Decision

Existing FREE users keep their plan. New signups blocked at Phase 5. Minimum paid tier = ECHO. This spec does not implement billing changes — only documents the policy.

Consequences

Publish pipeline itself is plan-agnostic. FREE block is a separate gate in signup flow.

ADR-009

Convex schema SSOT — schemas/publish.ts, no duplicated enums

Accepted
Context

Publish enums and validators risk duplication across Convex schemas, API validators, worker types, and frontend. Drift causes runtime mismatches.

Decision

All publish-related Convex validators live in packages/database/convex/schemas/publish.ts. Exported via schemas/index.ts. Registered in schema.ts. Worker error codes in packages/worker/providers/errors.ts map to errorClass at the API boundary — never redefined in Convex.

Consequences

Single file to update when adding statuses. API and frontend import types from @delulu/database/convex/schemas. See 07 — Schema for full DDL.
