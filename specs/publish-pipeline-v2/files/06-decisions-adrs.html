Hub / Architecture Decision Records

ADRs

Recorded decisions with context, choice, and consequences.

ADR-001

Keep Convex as system of record

Context: Team considered PlanetScale (MySQL/Vitess) to replace Convex. Publishing fragility was attributed to architecture, not Convex itself. Convex powers real-time UI, Clerk auth template, automations, approval workflow, aggregates, and search.

Decision: Convex remains system of record. PlanetScale deferred.

Consequences: No dual-write migration. Publish jobs live in Convex. Revisit PlanetScale only if 2+ decision-gate triggers fire (see 14 Risks).

Status: Accepted · 2026-07-04
ADR-002

One publish_job per post × provider per run

Context: Multi-platform posts queue N SQS messages but share one posts.status. Workers race and last-writer-wins corrupts state.

Decision: Introduce publish_jobs — one row per (postId, socialProviderId, runId). Each SQS message carries publishJobId.

Consequences: Postiz uses one Post per integration; we keep one editorial post with N jobs. UI shows per-platform chips.

Status: Accepted · 2026-07-04
ADR-003

Derive post publishStatus from jobs

Context: Worker currently sets posts.status to PUBLISHED or FAILED directly.

Decision: Worker only updates publish_jobs. A single Convex mutation derivePostPublishStatus runs atomically after each attempt completion.

Consequences: PARTIAL status when some providers succeed and others fail. Editorial lifecycleStatus unaffected by transient failures.

Status: Accepted · 2026-07-04
ADR-004

Worker writes via apps/api internal routes

Context: Worker uses ConvexHttpClient + public mutation. Tight coupling; no request validation layer.

Decision: Worker POSTs to apps/api/internal/publish/complete with HMAC (LAMBDA_SECRET_KEY). API calls Convex internal mutation.

Consequences: Single ingress for worker; easier to add logging, rate limits, and future non-Convex backends.

Status: Accepted · 2026-07-04
ADR-005

Webhook consolidation in Phase 4

Context: Clerk, Dodo, Call Me Later hit convex/http.ts. Instagram hits AWS Lambda.

Decision: Phase 4 moves Clerk/Dodo/CML to apps/api/webhooks/*. Instagram stays on Lambda (CF KV cache, Meta latency).

Consequences: Publish pipeline ships first without webhook URL changes. Dual endpoints during cutover.

Status: Accepted · 2026-07-04
ADR-006

Keep Convex subscriptions for real-time

Context: If PlanetScale were adopted, real-time dashboard would need replacement.

Decision: No change. Dashboard subscribes to posts and new publish_jobs queries.

Consequences: Zero UX regression on publish status updates.

Status: Accepted · 2026-07-04
ADR-007

Partial publish UX

Context: Instagram may succeed while Twitter fails on same post.

Decision: Show publishStatus: PARTIAL with per-platform status chips from publish_jobs.

Consequences: Calendar and posts list need chip UI. API returns per-job status in post detail.

Status: Proposed · pending product confirm
ADR-009

Convex schema single source of truth

Context: Duplicated enums and inline validators across mutations, API routes, and app types drift over time and are hard to maintain.

Decision: All publish-pipeline schema in schemas/publish.ts, re-exported via schemas/index.ts. schema.ts only registers tables. Functions import validators; app/API use Infer or const objects — never copy literal unions.

Consequences: One file to update when adding a job status or error class. Matches existing enums.ts + posts_media.ts pattern.

Status: Accepted · 2026-07-04
ADR-008

Remove FREE plan from new specs

Context: Constraint: minimum paid tier is entry point (ECHO).

Decision: Grandfather existing FREE users. Block new FREE signups. Remove FREE watermark logic from new automation paths over time.

Consequences: plans.ts, Dodo products, IG webhook planType === "FREE" paths need updates in Phase 5.

Status: Accepted · 2026-07-04
