Call Me Later — publish webhook (target)

POST /webhooks/callmelater/publish
Headers: x-api-key: CALLMELATER_API_KEY (or shared secret)
Body: { "postId": "k57..." }

Handler:
  1. Verify API key
  2. convex.mutation(publish.createRun, { postId, trigger: "scheduled" })
  3. Return 200 { success: true, runId }

Eliminates Convex HTTP → internal action hop. CML fires directly into publish pipeline.

Clerk webhook (target)

Move validateRequest (Svix) from convex/http.ts to apps/api/src/routes/webhooks/clerk.ts. Forward to existing Convex internal mutations:

  • internal.users.upsertFromClerk
  • internal.organizations.upsertFromClerk
  • internal.organizations.addMember / removeMember / updateMemberRole

Dodo webhook (target)

Port createDodoWebhookHandler callbacks to Worker route. Same mutation targets as today in convex/webhooks.ts.

Instagram — no move

Rationale: instagram-webhook.ts uses CF KV as a gate before Convex (~90% miss path avoids DB). Moving to Workers is possible but adds risk for the core DM automation moat. Defer unless CF Workers gains KV bindings in same account.

Zero-downtime cutover

  1. Deploy new apps/api/webhooks/* routes
  2. Keep Convex http.ts routes active (both receive events)
  3. Update Clerk/Dodo/CML dashboard URLs to new endpoints
  4. Monitor for 48h — dedupe via idempotent Convex mutations
  5. Remove Convex HTTP routes
