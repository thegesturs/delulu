Hub / Target Architecture

Target Architecture

Layer boundaries, data ownership, and control flow after v2.

Design principles

  1. Posts = editorial artifact — content, schedule intent, approval. Worker never patches post on failure.
  2. Publish jobs = execution artifact — one job per post × socialProvider per run.
  3. Derived post status — computed from child jobs inside a single Convex mutation.
  4. Single write API — worker calls /internal/publish/complete; mutation enforces invariants.
  5. Convex stays — real-time, automations, approvals unchanged.

Why not PlanetScale / NestJS / Temporal

  • PlanetScale — loses Convex real-time; XL migration for same job table we'd build anyway
  • NestJS — apps/api on Hono already exists; adding a second backend increases ops surface
  • Temporal — Postiz pattern is good but SQS+DLQ+Convex jobs achieves parity at lower complexity for current scale
