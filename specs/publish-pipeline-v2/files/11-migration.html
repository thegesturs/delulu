Hub / Migration Plan

Migration Plan

Phased zero-downtime rollout — no PlanetScale dual-write.

Strategy

Strangler fig inside Convex: additive tables → shadow → dual-write compare → cutover → cleanup. Webhook URLs change only in Phase 4.

Phase 0 — Instrument (3 days)

  • Ship this spec to specs/publish-pipeline-v2/
  • PostHog: publish_job_created, publish_attempt_started, publish_attempt_failed
  • Baseline: count current FAILED posts, multi-provider partial failures (manual audit)

Phase 1 — Additive schema (1 week)

  • Add packages/database/convex/schemas/publish.ts — all enums + base schemas (SSOT)
  • Export from schemas/index.ts; register tables in schema.ts
  • Deploy publish_jobs, publish_attempts to Convex
  • Add publishStatus, lifecycleStatus on posts via posts_media.ts (import publish enums, don't redefine)
  • Implement publish.createRun in shadow mode — creates jobs, logs only, still uses old queue path
  • No user-visible change

Phase 2 — Dual path (1 week)

  • SQS payload includes publishJobId
  • Deploy apps/api/internal/publish/*
  • Worker writes to new API and old mutation (compare logs)
  • Configure SQS DLQ + maxReceiveCount: 5
  • Fix hardcoded Lambda URL in post.service.ts → env var / SST output

Phase 3 — Cutover (3 days)

  • Remove worker → updatePostPublishStatus
  • publishScheduledPost → createPublishRun
  • createPostInQueue → createPublishRun
  • Derive legacy posts.status from jobs for UI backward compat
  • Wire failed-posts-alert.tsx retry
  • Feature flag: PUBLISH_PIPELINE_V2=true

Phase 4 — Webhooks (1 week)

  • Deploy apps/api/webhooks/*
  • Dual endpoints: Convex HTTP + Workers (48h)
  • Update Clerk, Dodo, CML dashboard URLs
  • Update CML targetUrl in callmelater.ts schedule calls
  • Remove convex/http.ts routes after verification

Phase 5 — Cleanup (3 days)

  • Stuck-job sweeper cron (PROCESSING > 15 min)
  • Deprecate platformPosts direct mutation — read from jobs
  • Remove shadow logging; remove feature flag
  • FREE plan: block new signups; grandfather existing

Rollback plan

PhaseRollback
1–2Disable shadow; no user impact
3Flip PUBLISH_PIPELINE_V2=false; worker uses old mutation
4Revert webhook URLs to Convex HTTP

Data migration

No backfill required for historical posts. Existing platformPosts[] remains read-only legacy data. New publishes write to publish_jobs. Optional: one-time script to create synthetic COMPLETED jobs from PUBLISHED posts for UI consistency.
