13 — Risks & Effort

Risk register, effort estimate, and decision gates for Publish Pipeline v2.

Deferred effort

PlanetScale migration = XL (~2–3 months). Explicitly out of scope. Would not fix the orchestration problem — only changes the storage layer.

Risk register

IDRiskLikelihoodImpactMitigation
R-01 Cutover causes publish outage Medium Critical Dual-path phase (Phase 2) with 7-day bake. Feature flag rollback to old path.
R-02 Instagram automations break on side-effect refactor Low High Extract side effects into tested function. AC-3.7 acceptance test. No automation code changes.
R-03 HMAC auth misconfiguration blocks all worker writes Medium High Integration tests for HMAC. Dual-path logs discrepancies. Alert on 401 rate spike.
R-04 API hop adds latency causing Lambda timeout Low Medium API → Convex call target < 200ms. Lambda timeout = 5 min. Monitor P99.
R-05 Convex table growth from attempt logs Medium Low TTL cleanup cron for attempts older than 90 days. Index-only queries for sweeper.
R-06 UI doesn't migrate to publishStatus in time Medium Medium Phase 3 blocked on UI PR. Fallback: read both status and publishStatus.
R-07 SQS DLQ fills with transient platform outages Medium Medium DLQ alarm + manual replay tool. Rate-limit error respects retryAfter.
R-08 Schema enum drift between Convex and worker Low Medium ADR-009 SSOT. Grep CI check for duplicate literals.
R-09 Org approval bypass via new API route Low High AC-3.9 test. Reuse existing requiresApproval check in publish endpoint.
R-10 Phase 4 webhook cutover drops events Low High Dual endpoints for 48 hours. Event count comparison before removing old URLs.

What success looks like

  • Multi-platform publish failure rate drops by >50% (transient errors now retry)
  • Zero "last platform wins" status corruption incidents
  • Mean time to diagnose publish failure < 5 minutes (attempt log + PostHog)
  • Dashboard retry resolves >80% of transient failures without support ticket
  • No regression in Instagram DM automation conversion rate

Alternatives considered

AlternativeWhy not
Migrate to PlanetScale + job table in SQL XL effort, doesn't fix orchestration, loses Convex subscriptions
Add NestJS microservice for publish New deployment, auth, monitoring overhead. apps/api sufficient.
Use Temporal / Step Functions for orchestration Heavy infrastructure for ~3 week problem. Convex tables + SQS sufficient.
Fix updatePostPublishStatus in place (add locking) Band-aid. Doesn't add retry, observability, or idempotency.
Client-side status aggregation Requires polling; breaks real-time subscription model.
Recommendation stands

Keep Convex. Add job orchestration. Route worker writes through apps/api. Phased migration with feature flags. Total effort M (~3–4 weeks) with acceptable risk profile.
