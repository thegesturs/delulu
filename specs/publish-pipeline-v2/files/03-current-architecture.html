Publish triggers

TriggerEntry pointQueue path
Publish nowupsertPost status=PROCESSINGConvex action → Lambda
ScheduleupsertPost status=SCHEDULEDCML → Convex HTTP → action → Lambda
Manual retrycreatePostFromPostId tRPCSets PROCESSING → createPostInQueue
Scheduled fireCall Me Later POST /publishPostConvex action → Lambda per provider

Data model (publish-related)

  • posts — content, schedule, status, embedded platformPosts[], retryCount
  • socialProviders — OAuth tokens, platform type
  • No publish_jobs or publish_attempts tables

Infrastructure (SST)

ResourceConfig
SocialPostsQueuevisibilityTimeout: 15 min, batch size 1
trigger-sqs LambdaURL endpoint, x-api-key auth → enqueue
social-post-worker LambdaSQS subscriber, 10 min timeout, links CONVEX_URL
InstagramWebhook LambdaCF KV gate → Convex automations
Note: ECS Task path is commented out in sst.config.ts. Worker runs as Lambda subscriber, not ECS.

Real-time

Dashboard, calendar, and posts list use Convex useQuery subscriptions. Post status changes propagate in real time — this is a strength to preserve.
