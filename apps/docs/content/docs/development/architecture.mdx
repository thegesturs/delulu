Delulu keeps one domain model behind several runtime adapters.

```text
human consent ─┐
               ├─ authenticated app ─┐
agent ─ MCP ───┤                     │
agent ─ CLI ───┼─ typed API ─ PostgreSQL ─ publisher ─ social networks
code  ─ REST ──┘          │
                          └─ object storage
```

## Applications

- `apps/app`: authenticated Next.js product.
- `apps/web`: public marketing and utility site.
- `apps/api`: typed API with Cloudflare and Node entrypoints.
- `apps/docs`: this documentation site.
- `apps/cli`: deterministic command-line interface for people and agents.
- `apps/mcp`: MCP server and tool definitions.

## Domain modules

- `packages/contracts`: public request, response, and error schemas.
- `packages/core`: domain types and policies.
- `packages/services`: Effect services and use cases.
- `packages/db`: forward-only PostgreSQL migrations and tooling.
- `packages/worker`: hosted and PostgreSQL publishing runtimes.
- `packages/connections`: provider definitions, OAuth, validation, and publishing adapters.

## Connection runtime split

`@delulu/connections` is safe in both workerd and Node. It contains metadata, OAuth, rules, settings, webhooks, queries, the provider registry, token services, and the shared error model.

`@delulu/connections/worker` adds Node-only publishing dependencies. The isomorphic entrypoint must never import publishing runtime files. Publisher failures are classified as retryable or permanent at this seam so queue and PostgreSQL transports preserve the same behavior.
