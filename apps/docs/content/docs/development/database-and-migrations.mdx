title: Database and migrations
description: Develop against PostgreSQL, ship forward-only migrations, and use the legacy import tool safely.
---

`@delulu/db` owns forward-only plain SQL migrations. Primary and foreign keys are application-generated, entity-prefixed IDs stored as text.

## Local database

```bash
pnpm pg:up
pnpm pg:migrate
pnpm pg:migrate:status
pnpm pg:migration-lint
```

The local database defaults to `postgres://delulu:delulu@localhost:5432/delulu`.

## Production migrations

Production migration jobs must use a direct TLS PostgreSQL connection on port `5432`, not a transaction pooler. The production build validates the database host and applies pending migrations before deploying the API. A failed migration stops deployment.

Keep migrations compatible with the currently deployed application. Add and backfill first, deploy code that no longer depends on the old shape, and remove the old shape in a later release.

## Legacy data import

`@delulu/migrate-convex` is the one-off import and verification CLI:

```bash
pnpm --filter @delulu/migrate-convex exec tsx src/main.ts inspect --snapshot export.zip
pnpm --filter @delulu/migrate-convex exec tsx src/main.ts run --snapshot export.zip
pnpm --filter @delulu/migrate-convex exec tsx src/main.ts verify --snapshot export.zip
pnpm --filter @delulu/migrate-convex exec tsx src/main.ts report --snapshot export.zip
```

`run` refuses non-local databases unless `--confirm-database <host>` matches the configured host. It validates the migration head before truncating tables. Verification covers counts, references, domain invariants, sampled equality, encrypted tokens, quotas, ownership, and role mapping.

For a production import, run and verify twice from the same export, then review the generated ownership, role, and edge-case reports before routing traffic.
