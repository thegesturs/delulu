---
title: Provider development
description: Add a social provider without crossing the browser, edge, and Node runtime boundary.
---

`@delulu/connections` is the source of truth for social-platform connections. The package deliberately exposes two runtime entry points:

| Import | Runtime | Responsibility |
| --- | --- | --- |
| `@delulu/connections` | Edge and Node | Metadata, OAuth, rules, settings, webhooks, queries, token services, and the isomorphic registry |
| `@delulu/connections/worker` | Node only | The isomorphic surface plus publishing adapters and the `runPublish` boundary |

`packages/connections/src/index.ts` must never import `publish.ts`, `publish-registry.ts`, or `runtime.ts`. Publishing dependencies do not run in the edge API. `definition.ts` therefore has no `publish` field.

## Add a provider

1. Use an existing folder under `packages/connections/src/platforms/` as the structural reference.
2. Implement metadata, authentication, rules, settings, and publishing. Add webhooks or queries only when the provider supports them.
3. Register the isomorphic definition in `registry.ts`.
4. Register the Node publisher in `publish-registry.ts`.
5. Add focused tests for OAuth state, callback errors, media rules, retry classification, and the publishing response.
6. Run the connections and worker typechecks and tests before opening a pull request.

OAuth callbacks persist exclusively through the API-provided PostgreSQL seam. Do not introduce a fallback storage path.

Publishers return an Effect whose typed failure identifies the provider, stable error code, message, and whether retrying is safe. The worker boundary retries only retryable failures; invalid media, rejected posts, missing profiles, and other permanent failures must terminate cleanly.

```bash
pnpm --filter @delulu/connections typecheck
pnpm --filter @delulu/connections test
pnpm --filter @delulu/worker typecheck
pnpm --filter @delulu/worker test
```
