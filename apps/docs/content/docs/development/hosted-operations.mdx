This page covers the commercial hosted deployment. Community operators should use the [self-hosting guide](/self-hosting/).

## API and publishing

The Cloudflare API handles typed HTTP requests and webhooks. The hosted publishing lane uses SQS and the Node worker.

Before production deployment:

```bash
pnpm --filter @delulu/http-api typecheck
pnpm --filter @delulu/infra typecheck
pnpm --filter @delulu/connections typecheck
pnpm --filter @delulu/worker typecheck
pnpm --filter @delulu/worker test:integration
```

Verify a scheduled target moves through pending, dispatched, and completed states; the target becomes published; the primary queue drains; and the dead-letter queue remains empty.

## Messaging

The API supports Cloudflare Email Service for transactional mail and Loops for opted-in lifecycle messaging. Configure `CLOUDFLARE_EMAIL_FROM`, `LOOPS_API_KEY`, `CAL_WEBHOOK_SECRET`, and `CAL_RETENTION_EVENT_SLUG` in the deployment platform. Clerk remains the source for authentication, account-security, invitation, and role-change mail.

Lifecycle mail must respect preferences, cancellation state, quiet periods, and global frequency limits. Webhook delivery is safe to retry because event claims and billing transitions are durable.

Use the [email lifecycle runbook](/development/email-lifecycle/) to configure domains, calendar and billing webhooks, workflow events, suppression rules, and deletion operations.

## Analytics proxy

`NEXT_PUBLIC_POSTHOG_PROXY_HOST` is optional. When configured, the analytics client falls back to that host if the direct endpoint cannot be reached. Verify direct and proxied event delivery before releasing.

Use the [analytics proxy runbook](/development/analytics-proxy/) to deploy the Worker, configure the custom domain, and verify direct and fallback delivery.

Never commit provider tokens, signing keys, production database URLs, or environment-specific publishable keys to documentation.
