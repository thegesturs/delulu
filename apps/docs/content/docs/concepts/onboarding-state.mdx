---
title: Onboarding state
description: How explicit onboarding completion stays separate from account and billing readiness.
---

## Completion truth

Onboarding completes when the user finishes the guided web flow or an
authenticated client calls the setup completion endpoint. The web flow stores
one goal:

- `publish`, which is ready after any supported publishing account connects
- `auto_dm`, which is ready after an Instagram account connects

The setup response derives `webStep` as `goal`, `connect`, `ready`, or
`complete` from that saved goal, the authoritative connection list, and final
completion. Browser clients must not persist a separate numeric wizard step.

Account callbacks and payment webhooks may refresh setup status, but they never
reverse explicit onboarding completion. A subscription is not required to
finish activation or enter the workspace; paid capabilities and account limits
show upgrade choices at the point they are reached.

## Connection returns

Browser connection state can include a signed return target. Account settings
uses `socials`, while onboarding uses `onboarding-connect` and returns to the
connection step for success, cancellation, provider errors, and transfer
confirmation. Clients that omit a return target retain the account-settings
behavior.

Legacy signed states remain accepted during the callback rollout. Invalid or
expired state returns a safe browser result page rather than an API error body.

## Optional prompts

Referral attribution is a dismissible post-activation prompt. It does not
participate in `webStep` and never blocks access to the workspace.

## Compatibility mirror

The backend owns completion truth and mirrors it into identity-provider public
metadata so existing middleware and browser routing continue to work. Clients
should read the authenticated setup-status or workspace-overview response
instead of inferring state from metadata or URL query parameters.

## Outstanding actions

The setup response returns one highest-priority action:

- `connect_account`
- `complete_payment`
- no outstanding action when account and billing readiness are satisfied

These readiness actions are independent of `onboardingComplete`. The CLI
overview also adds operational next actions such as expiring connections,
failed publications, pending reviews, active publications, upcoming schedules,
and first-post creation.
